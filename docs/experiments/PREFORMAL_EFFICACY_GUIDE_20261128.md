# MorphoFlow-IHC 创新机制预实验与效能门槛

适用基线：分支 `run/preformal-smoke-20261128`，代码基线 `273f2f8` 及与之目标一致的后续提交。本文专门补上“模块是否改善目标问题”的验证；它不是代码能否运行的 smoke-test 清单。

## 结论先行：目前的预检只证明工程链路

2026-11-28 的 28 项测试、Flow 8 次更新、PPO 8 组更新和单张推理，说明数据缓存、梯度更新、checkpoint 与推理链路可运行。奖励差超过门槛也只说明 PPO 收到可区分的数值信号。它们**没有验证区域 CFM 是否比像素监督更抗错位、PatchNCE 是否保留结构、PPO 是否改善未见样本的染色结果**。

因此预检结论应分开记录：

- **工程就绪：通过**（以报告中的代码、GPU、缓存哈希为准）。
- **创新机制有效性：尚未验证**。
- 不能把这次 smoke-test 写成模块有效证据，也不能只凭它决定论文中的效果主张。

## 当前要验证的机制及可证伪预测

当前实现包含区域 CFM、PatchNCE、PatchGAN 外观监督和 PPO 区域策略。模块说明以 [METHOD.md](../METHOD.md) 为准。

| 机制 | 要验证的主张 | 对照只改什么 | 主要观察量 |
|---|---|---|---|
| 四相位区域 CFM（默认区域 64 px） | 对小范围配对错位较逐像素 CFM 更稳，同时保留区域表达信息 | 同一初始化、训练样本顺序和更新数，仅把区域聚合换成逐像素目标；若代码无此开关，先加显式开关，默认必须保持现有目标 | 人工已知位移压力测试下的区域速度误差；留出配对图上的 64/128 px DAB 支持与总量误差；无位移场景的退化幅度 |
| PatchNCE | 限制生成图偏离输入 H&E 的形态结构 | 同一初始化与训练计划，仅将 `nce_weight` 设为 0 | 固定、非训练的苏木素/边缘结构代理；局部结构图；并同时报告 DAB 区域误差，防止“结构像但表达不对” |
| PatchGAN | 补足 IHC 染色外观分布 | 同一初始化与训练计划，仅将 `adversarial_weight` 设为 0 | 留出 IHC 上 DAB OD 与颜色分布距离/直方图；同时报告漏染、额外染色和结构代理。小样本 FID 只能作描述，不能当决定性指标 |
| PPO 区域动作 | 学到的速度修正能改善留出区域染色，而非仅改变图像或提高自身训练奖励 | 同一个 Flow 起点；PPO 策略训练与零动作续训比较；推理时另做同一联合 checkpoint 的策略开/关成对比较 | 未参与 PPO 更新的样本上，64 px 支持 F1/误差与 DAB 量误差；128 px 奖励另列，不把训练奖励本身当独立验证 |

这里的“提高”不是细胞级 HER2 识别结论。配对数据是相邻组织切片，区域目标仍受错位影响；不能据此声称模型知道某一个具体细胞为什么阳性。

## 最小而有信息量的效能预实验

### A. 冻结一份开发清单，保护官方测试集

1. **绝不使用官方 1,000 对 `valA/valB` 试阈值、选权重、挑 checkpoint 或评估预实验。** 它是最终测试队列，不是开发集。
2. 从官方 4,642 对训练队列建立一次性、固定的 pilot 清单：建议留出 128 对作 pilot-dev，其余用于 pilot-train；同一病例/来源可识别时按最高层级分组。清单和哈希固定后，各实验臂共用完全相同的 ID、裁块坐标、增强随机数和评估脚本。
3. 数据目前未证实患者 ID。若只能按 `source_prefix` 分组，需在报告中写明这是来源前缀分组、**不是患者独立验证**；若前缀不足以隔离相邻切片，按图像配对层级做的结果仅能当工程性探索。
4. 这 128 对只用于设计筛查，结果看完后不得反复换清单。方法和参数冻结后，它们可以回到正式训练集；正式效果结论仍只由锁定后的最终测试流程支持。

### B. 做一次区域错位机制压力测试

在固定的 pilot-train 配对裁块上，对参考 IHC 作已知的 `(dx,dy)` 平移：`(0,0)`、`(±4,0)`、`(0,±4)`、`(±8,0)`、`(0,±8)`、`(±16,0)`、`(0,±16)` px；另记录 32 px 作为超出小错位范围的压力条件。平移只用于诊断，不写入真实训练清单，也不构造病理标签。

对逐像素 CFM 与 64 px 四相位区域 CFM，分别计算目标速度损失及预测梯度变化，并记录平移增大时的曲线。预期：区域目标在小位移下更平滑/稳定，而非声称对大错位不敏感。须同时查明无位移时区域目标是否明显损失边界与局部表达信息。输出一张误差—位移曲线和若干真实组织例图。

若当前训练代码没有“逐像素 CFM / 区域 CFM”可切换的实现，不能用文字推断实验结论；先实现一个只切换聚合方式的配置项，确保默认值与现行区域 CFM 完全一致，并给两种模式共用同一目标速度、掩膜和归一化。不得改动额外损失或训练计划。

### C. 做匹配的单因素训练筛查

最小筛查包含以下成对对照，建议每臂 **1,000 次生成器优化更新**，并记录 PPO 实际策略组数。1,000 更新是短程筛查预算，**不是收敛证明**。如果曲线尚未进入稳定下降区，结果标记为“未决”，不能以短程胜负筛选最终论文结果。

| 对照 | 参考臂 | 消融/基线臂 |
|---|---|---|
| 区域 CFM | 64 px 四相位区域 CFM | 逐像素 CFM |
| PatchNCE | 完整生成器目标 | 仅 `nce_weight=0` |
| PatchGAN | 完整生成器目标 | 仅 `adversarial_weight=0` |
| PPO | 相同 Flow checkpoint 上联合 PPO 策略训练 | 从同一个 Flow checkpoint 出发、相同生成器更新数的零动作续训 |

每一对对照必须匹配：初始化 checkpoint、样本曝光量、样本次序、随机裁块/增强、seed、batch、有效 AMP 精度、学习率日程、优化器更新数和 EMA/保存规则。一次只改表内的一项。记录额外候选轨迹带来的 PPO 计算成本；若更新数相同但 wall-clock 不同，分别报告“等更新数”和真实耗时，不能宣称等计算量。

实现中若没有训练期 `NCE off`、`adversarial off`、`pixel CFM` 或 `zero-action` 的受控入口，先添加显式配置并加默认值回归检查；不要通过临时手改代码或更换多个配置项拼出不干净的消融。所有臂使用新的输出目录，保存完整配置与 hash。

### D. 在固定 pilot-dev 上评估，指标对应机制

所有臂在相同的 128 对 pilot-dev 上推理/比较；随机 seed、输入尺度、裁块坐标、组织掩膜和后处理保持一致。

- **表达/区域 CFM：**以真实 IHC 的 H-DAB/OD 代理计算 64 px 和 128 px 区域的支持 F1、支持比例误差、DAB 总量相对误差；按相位分别报告，再给均值。不能把窗口数量当独立样本。
- **形态/PatchNCE：**对 H&E 输入和生成 IHC 使用冻结、非训练的 stain-deconvolution + 边缘描述器，报告带小位移容差的结构相似代理及示例。另报 IHC 参考形态的区域级相似性；切片差异可能造成局部结构不一致，不能解释成精确细胞对应。
- **染色外观/PatchGAN：**只在有效组织内比较参考与生成的 DAB OD 分布和 RGB/光密度色彩距离；同时检查背景误染、额外 DAB 与 DAB 欠量。外观距离变好但表达支持变坏，不算整体有效。
- **策略/PPO：**对同一联合 checkpoint，以相同 H&E、随机种子分别运行策略开启、零动作关闭；可加同幅度随机动作作“动作幅度”对照。训练策略的成对比较还要对照相同 Flow 起点、相同生成器更新数的零动作续训。主评价用 64 px 留出尺度的区域误差/支持 F1，避免只复用 PPO 训练时的 128 px 奖励。
- **图像审查：**固定显示 12–20 个 pilot-dev 案例，覆盖弱/强 DAB、稀疏/密集表达和组织边缘；所有模型使用相同输入。图像用于解释数值，不能只挑改善样例。

用配对差值和预先固定的 bootstrap 区间汇总，重采样单位应是患者/标本。若只有 `source_prefix`，就按该单位给描述性区间并标注身份不明；若连可靠分组也没有，不得把大量 patch/window 当独立样本制造很窄的区间。小 pilot 不够形成统计结论时直接写“方向性/未决”。

### E. 预先写明的判定规则

在运行前把每项主指标、方向、非劣 guardrail 与分析脚本 hash 写入 pilot 配置。不要看结果后再改主要指标或阈值。没有适用于所有指标的统一“提升百分比”；最小有意义差值应根据固定评测的重复性/量化分辨率预先确定。

- **区域 CFM 支持：**小位移压力曲线更稳，且无位移时 64/128 px 的表达误差没有超过预设容忍范围的退化。
- **PatchNCE 支持：**结构代理相对 NCE-off 改善，同时 64/128 px 表达指标不出现预设范围外的下降。
- **PatchGAN 支持：**外观分布距离改善，且误染、漏染和结构 guardrail 不恶化。
- **PPO 支持：**训练后策略在未参与 PPO 更新的 pilot-dev 上，较零动作/零动作续训改善预先指定的区域指标；仅 reward 上升、输出有变化或 PPO 更新被接受不算支持。
- 若置信区间宽、结果在来源间不一致或多个护栏方向相反，结论为“未决/不支持当前强主张”，不能用训练损失更低替代效果证据。

## 对 411e0fe 预检结果的判读与下一步

这次 6 个实验臂每臂 2 次更新，适合确认开关和控制路径，不适合据此判断模块效果。两个 CFM 的原始 loss 定义和尺度不同，不能用 `0.376` 对 `1.393` 宣称区域目标更好；NCE-off/GAN-off 的零损失只证明关闭路径生效。

pilot-dev 虽有 128 对，但只来自 **2 个 source_prefix**。这能做代码评估流程和图像抽查，不能支持跨来源的效果判断，也不适合做来源层级 bootstrap 推断。下一版固定 dev 清单应尽可能覆盖训练队列中所有可用前缀；若可用前缀足够，优先覆盖至少 10 个前缀、每个前缀取若干对，而不是从两个前缀集中抽 128 对。这个数量只是筛查覆盖度建议，不等于患者独立或统计效能保证。若可用前缀少于 10 个，报告实际数量，结论保持描述性。

### PPO 的直接诊断步骤

本次 PPO 两组 spread 为 `3.58e-6`、`6.68e-6`，低于 `1e-5` 门槛，`accepted=0`。这说明这两组没有学到策略更新；两组太少且起点仅有极少 Flow 更新，不能据此判定 PPO 机制有效或无效。不要直接降低门槛，也不要用增加组数来掩盖候选动作几乎相同的问题。

下一步先用固定的多前缀 pilot-dev，在一个已能产生非平凡 DAB 输出的 Flow checkpoint 上做 **候选动作诊断**，不更新权重；至少覆盖 32 个不同状态/ROI。逐候选保存：策略动作值与标准差、实际速度修正范数、策略开/关输出差、奖励总分及 support/amount 分量、组内 spread、signal fraction。奖励计算用 FP32 复算一份，用来识别 BF16 量化或阈值化导致的差异压扁。检查结果可区分三种情况：

1. 动作值/速度修正几乎为零：检查策略初始化、动作缩放和动作注入位置。
2. 速度修正不小但输出几乎不变：检查四步积分中动作的实际生效路径和 RGB 反归一化/裁剪。
3. 输出有差异但奖励几乎不变：检查奖励对该类变化是否敏感、support 阈值/掩膜及奖励分量的尺度。

若候选动作有可观差异而奖励仍无有意义排序，问题在奖励目标或尺度；这时才修改奖励设计，并重跑受控的奖励排序测试。若仅在极少状态低于门槛，继续记录 skip 是正确行为。完成诊断后再做更长 PPO pilot，并在未用于 PPO 更新的多前缀 dev 上比较策略与零动作的区域表达误差。训练奖励或 `accepted>0` 本身都不是效能证据。

### 训练臂的后续安排

先完成上面的奖励诊断与多前缀开发清单，再启动匹配的效果筛查。1000 更新/臂只能作为初筛预算：必须同时生成并评估 dev 输出；若曲线仍明显处于冷启动、排名随 checkpoint 波动或区间很宽，结论仍为“未决”，不能据此宣称模块有效。对区域 CFM、NCE、GAN 的比较使用成对差值和各自对应的独立指标，不跨不同损失的原始数值排序。后续资源有限时优先验证两项核心主张：区域 CFM 的位移稳健性、PPO 学得的区域速度修正在 held-out dev 上是否优于零动作；其余损失作为结构/外观护栏，不需重复堆大量无关实验。

## 正式实验放行口径

完成现有工程 smoke test 后，可称“工程管线可运行”，不能称“创新有效”。完成上述机制压力测试和匹配 pilot 后，才能判断哪些模块值得进入正式 40+10 训练及论文主张；pilot 仍不替代完整训练、最终锁定的官方 1,000 对测试评估，或独立病理任务验证。测试集只在实验决定冻结后运行一次最终协议。

## 2026-11-28 本地训练预检结果

在分支 `run/preformal-efficacy-20261128` 完成了每臂 2 次更新的工程预检：区域/像素 CFM、NCE-off、GAN-off，以及 PPO/零动作两组对照。28 项测试通过，所有训练臂均生成格式 11 checkpoint。详细配置、GPU 日志、hash 和局限见[预检结果](../../artifacts/preflight_efficacy_20261128/RESULTS.md)。

该运行**没有达到本指南建议的 1,000 更新/臂，也没有评估 128 对 pilot-dev**，所以只确认开关和训练路径可运行，不回答模块是否有效。短测的 PPO 奖励 spread 两组均低于 `1e-5` 门槛，`signal_fraction=0`、`accepted=0`。创新效能仍未验证；正式训练和论文主张不能据此放行。

## 2026-11-29 多来源 PPO 后续筛查

随后将 pilot-dev 扩展到 128 对、覆盖全部 61 个训练来源前缀，并从 pilot-train 训练 Flow1000、PPO1000 和零动作续训1000。来源前缀不是经核验的患者 ID，结果只能按前缀做描述性比较。PPO 动作尺度扫描后，在 `velocity_limit=1.0` 下重跑 PPO1000；原 `min_reward_spread=1e-5` 未变，1000 组的采样日志 `signal_fraction=1.0`、`accepted=2`。

在同一固定 128 对、同裁块与噪声的 FP32 评估中，PPO-on 的 128 px support MAE 为 `0.26069`，零动作续训为 `0.27271`；PPO-on 的 DAB 总量相对误差为 `1.27362`，零动作为 `1.61097`。PPO-on 对零动作的来源前缀等权 95% 描述区间分别为 `[-0.01723,-0.00780]` 和 `[-0.40684,-0.27543]`。同一 PPO checkpoint 关掉策略后，128 px MAE 为 `0.27011`、DAB 相对误差为 `1.47612`，说明策略开关有可测差别。

这是一条方向积极的探索性结果，**不能视为确认性效能证明**：`velocity_limit=1.0` 是看过同一 pilot-dev 的尺度扫描后挑选的，存在开发集选择偏差；前缀未证实为患者；support F1 在所有模型上完全相同，当前阈值没有区分能力；DAB 总量误差仍大。官方测试集未使用。完整日志、数值结果、配置/数据/权重哈希与限制见[本轮归档](../../artifacts/ppo_candidate_diagnostic_20261129/REPORT.md)。
