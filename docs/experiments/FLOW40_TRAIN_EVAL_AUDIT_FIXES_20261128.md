# Flow40 training/evaluation audit fixes — 2026-11-28

This note records concrete corrections after auditing the weak Flow40 MIST HER2 result. It does not overwrite or reinterpret the historical metrics in `artifacts/flow40_official_test_20261128/REPORT.md`.

## Training-path correction

Before this fix, `StainFlow.losses` trained CFM on a conditional bridge state, then reused that same state and its velocity prediction to form the image consumed by PatchNCE and PatchGAN. The state is an interpolation between random source noise and paired target IHC. It is therefore not an inference sample and can expose target information to the auxiliary losses through the bridge state.

Now, `StainFlow.losses` keeps the regional CFM velocity objective and separately samples independent Gaussian noise for a differentiable `sample_rgb` rollout. PatchNCE and PatchGAN see that four-step noise-to-image output, the same path used at inference. In joint updates, the configured policy is used by that rollout. This is a method/training-objective change, not just a post-processing fix; old Flow40 weights cannot validate the corrected objective. It also adds several velocity-network evaluations per update, so training throughput will be lower than the one-step-shortcut run.

## Evaluation-path corrections

- Fiji and FID reference staging now removes stale image files, refreshes every expected image, and checks each staged file's SHA-256 rather than trusting equal file size.
- Both the standardized comparison evaluator and the regional-diagnostic evaluator assign every image a deterministic, pair-specific noise seed derived from the base seed and `(source_prefix, filename)`. The seed is saved alongside its per-image metric row.
- Prediction reuse now requires exact IDs, a matching provenance sidecar (weights/config/manifest hashes, checkpoint step, seed policy and inference path), and matching hashes for all prediction files. A directory from the previous evaluator cannot be silently reused.
- Full checkpoints are checked against the supplied evaluation config. Both evaluators require a verifiable checkpoint step (from checkpoint metadata or an explicit CLI value), rather than hardcoding 185,680, and record the configured number of Euler steps.
- Fiji results are accepted only when the macro logs the expected `DONE count=...` marker and the CSV passes exact-ID, 1024×1024, 8-bit validation. CSV and log are copied into the result directory. A nonzero launcher exit is retained as a warning rather than hidden.
- The evaluator keeps legacy PSNR/SSIM/Rc/Rp/Rave fields for protocol continuity but explicitly labels Rc/Rp/Rave as proxies. Those fields are not evidence of cell-level morphology correctness for serial sections.

## What this means for the old result

The values in the Flow40 report remain the historical values generated by the old training/evaluation path. The earlier evaluator used the same numeric noise seed for every image, despite describing it as a per-image seed, and its staging reused files based on byte count. This audit does not show that the old files were necessarily wrong; it shows that the procedure was not sufficiently auditable. Recompute with the corrected evaluator and a checkpoint trained under the corrected loss path before comparing methods.

No long training or corrected full-cohort reevaluation was started as part of this patch. No quality claim is made from this code change alone.
